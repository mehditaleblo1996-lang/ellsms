۱شروع سریع

با API پیامک داتیس رایان گستر ایرانیان، نرم‌افزار، فروشگاه یا سامانه‌ی شما بدون ورود به پنل پیامک می‌فرستد، وضعیت تحویل را می‌گیرد و موجودی اعتبار را می‌بیند. همه‌ی درخواست‌ها JSON هستند و از HTTPS ارسال می‌شوند.

۱

کلید بسازید

در پنل، بخش «توسعه‌دهندگان ← کلیدهای API»، یک کلید با دسترسی‌های لازم بسازید.

۳

۲احراز هویت و کلیدها

هر درخواست باید یک کلید API معتبر داشته باشد. کلید را فقط در هدر بفرستید؛ کلیدی که در آدرس (query string) بیاید پذیرفته نمی‌شود.

HEADERS
Authorization: Bearer datis_live_a1b2c3d4e5f6_kQ3fZ8...
Content-Type: application/json
کلید فقط یک بار نمایش داده می‌شود

بلافاصله پس از ساخت، آن را در جای امنی (مثل متغیر محیطی سرور) ذخیره کنید. داتیس رایان گستر ایرانیان خودِ کلید را نگه نمی‌دارد و قابل بازیابی نیست؛ اگر گم شد، کلید را چرخش (rotate) دهید یا کلید تازه بسازید. هرگز کلید را در کد سمت مرورگر یا اپلیکیشن موبایل قرار ندهید.

کلیدهای جدید با datis_live_ شروع می‌شوند. کلیدهایی که پیش از تغییر نام ساخته شده‌اند و با ellsms_live_ شروع می‌شوند همچنان معتبرند و نیازی به تعویض ندارند.

۴ارسال تکی و گروهی

POST/api/v1/messages

یک متن را برای یک یا چند شماره می‌فرستد. این درخواست همزمان است: پاسخ، نتیجه‌ی نهایی ارسال را در خود دارد و نیازی به پیگیری جداگانه نیست. دسترسی لازم: messages:send

فیلدهای درخواست

فیلدوضعیتتوضیح
destinationsاجباریآرایه‌ای از شماره‌ها (رشته)، حداکثر ۱۰۰ عدد. شکل‌های 0912… و 98912… هر دو پذیرفته و خودکار یکسان می‌شوند.
contentاجباریمتن پیام، حداکثر ۲۰۰۰ نویسه. پیام‌های طولانی خودکار چندبخشی ارسال و به همان اندازه محاسبه می‌شوند.
originatorاختیاریخط ارسال‌کننده. باید یکی از خطوط مجاز صاحب کلید باشد (اختصاصی، سازمانی یا اشتراکی). اگر نفرستید، خط پیش‌فرض پنل استفاده می‌شود.
channelاختیاریsms (پیش‌فرض)، bale یا bale_sms — جدول پایین.
client_message_idاختیاریشناسه‌ی یکتای شما برای جلوگیری از ارسال تکراری (بخش ۷).

وضعیت ارسال

statusکد HTTPمعنی
sent201به همه‌ی گیرنده‌ها ارسال شد.

۵ارسال انبوه و تدریجی

POST/api/v1/bulk-jobs

برای هر گیرنده متن خودش را دارید، یا تعدادشان از ۱۰۰ بیشتر است. درخواست در صف قرار می‌گیرد و شما یک شناسه برای پیگیری دریافت می‌کنید. دسترسی لازم: bulk:write

هدر Idempotency-Key در این مسیر اجباری است

برای هر کمپین یک مقدار یکتا بسازید (مثلاً campaign-1405-07-invoices). اگر درخواست قطع شد و دوباره فرستادید، با همان کلید کمپین دوباره ساخته نمی‌شود.

فیلدهای درخواست

فیلدوضعیتتوضیح
typeاجباریp2p، smart یا gradual — جدول پایین.
titleاجباریعنوان کمپین؛ در گزارش‌های پنل با همین نام دیده می‌شود.
itemsاجباریآرایه‌ای از {"mobile", "content"}، حداکثر ۵۰۰۰ ردیف.
originatorاختیاریخط ارسال‌کننده، با همان قاعده‌ی ارسال تکی.
throttle_countفقط gradualتعداد پیامک در هر نوبت (عدد صحیح ≥ ۱).
throttle_minutesفقط gradualفاصله‌ی بین نوبت‌ها به دقیقه (عدد صحیح ≥ ۱).

مقادیر type

typeرفتار
p2pارسال نظیربه‌نظیر: هر ردیف با متن خودش، با بیشترین سرعت ممکن.
smartاز نظر ارسال دقیقاً مانند p2p است؛ فقط در گزارش‌ها با برچسب «پیامک هوشمند» نمایش داده می‌شود.
gradualارسال تدریجی: هر throttle_minutes دقیقه، throttle_count پیامک.

۶پیش‌نمایش هزینه

پیش از ارسال واقعی، می‌توانید همان بدنه‌ی درخواست را به مسیر پیش‌نمایش بفرستید تا هزینه را ببینید:

POST/api/v1/messages/preview
POST/api/v1/bulk-jobs/preview

پاسخ شامل تعداد گیرنده‌های معتبر، تعداد بخش‌های هر پیام، هزینه‌ی تخمینی، موجودی پیش و پس از ارسال و اثر آن بر سهمیه است.

پیش‌نمایش هیچ چیزی را تغییر نمی‌دهد

نه پیامی ارسال می‌شود، نه اعتباری رزرو می‌شود و نه از سهمیه کم می‌شود. هرچند بار که بخواهید می‌توانید آن را صدا بزنید و به Idempotency-Key هم نیازی ندارد.

پیش‌نمایش تخمینی است: هنگام ارسال واقعی، هزینه دوباره محاسبه و همان لحظه رزرو می‌شود. اگر در این فاصله موجودی کافی نباشد، ارسال با خطا متوقف می‌شود — هرگز بیش از موجودی برداشت نمی‌شود.

۷جلوگیری از ارسال تکراری

شبکه همیشه قابل اعتماد نیست. اگر درخواست شما با خطای زمان‌انتظار (timeout) قطع شد، نمی‌دانید پیامک رفته یا نه. ارسال دوباره‌ی بی‌گدار ممکن است به مشتری دو پیامک برساند و دو بار هزینه بگیرد.

راه‌حل: به هر ارسال یک شناسه‌ی یکتا از طرف خودتان بدهید — مثلاً شماره‌ی سفارش:

BODY
{ "client_message_id": "order-1024-confirm", "destinations": [...], "content": "..." }

یا همان مقدار را در هدر Idempotency-Key بفرستید. سپس:

اگر دوباره بفرستید…نتیجه
با همان شناسه و همان بدنههمان پاسخ قبلی برمی‌گردد. پیامکی دوباره ارسال نمی‌شود.
با همان شناسه ولی بدنه‌ی متفاوتخطای 409 conflict — شناسه را اشتباهاً تکرار کرده‌اید.
وقتی درخواست اول هنوز در جریان استخطای 409 — کمی بعد دوباره امتحان کنید.

این شناسه برای /messages تا ۲۴ ساعت معتبر است.

بررسی امضا — حتماً انجام دهید

هر درخواست وبهوک این هدرها را دارد. با بررسی امضا مطمئن می‌شوید درخواست واقعاً از داتیس رایان گستر ایرانیان آمده و دست‌کاری نشده است:

HEADERS
X-Datis-Event-ID:  52bbf726-b067-4443-8a5c-ea4fe11a4f8b
X-Datis-Timestamp: 1754392345
X-Datis-Signature: 3f29a1…   (hex HMAC-SHA256)
FORMULA
signature = hex( HMAC_SHA256( secret, timestamp + "." + raw_body ) )
PHP
<?php
function verify_webhook(string $secret, string $timestamp, string $rawBody, string $signature): bool {
    // reject stale or replayed deliveries (5 minutes)
    if (!ctype_digit($timestamp) || abs(time() - (int)$timestamp) > 300) return false;
    $expected = hash_hmac('sha256', $timestamp . '.' . $rawBody, $secret);
    return hash_equals($expected, $signature);   // constant-time
}
نکته‌ها

raw_body باید همان بایت‌هایی باشد که دریافت کرده‌اید، پیش از هر json_decode. سریع با کد 2xx پاسخ دهید و پردازش سنگین را بعداً انجام دهید. با X-Datis-Event-ID رویدادهای تکراری را تشخیص دهید.

هر درخواست همین سه مقدار را با نام‌های قبلی (X-ELLSMS-Event-ID، X-ELLSMS-Timestamp و X-ELLSMS-Signature) هم دارد تا گیرنده‌هایی که پیش از تغییر نام نوشته شده‌اند بدون تغییر کار کنند.

403forbiddenکلید دسترسی لازم را ندارد، یا آی‌پی شما مجاز نیست.
403feature_not_availableاین قابلیت در پلن فعلی نیست.
404not_foundمسیر یا شناسه وجود ندارد.
409conflictشناسه‌ی ضدتکرار با بدنه‌ی دیگری استفاده شده، یا درخواست قبلی هنوز در جریان است.
413payload_too_largeبدنه بیش از ۲۵۶ کیلوبایت است؛ آن را چند قسمت کنید.
422validation_failedفیلدی ایراد دارد؛ جزئیات در fields. مثلاً originator: not_allowed یعنی این خط به شما تعلق ندارد.
429rate_limitedبیش از حد مجاز درخواست زدید؛ به اندازه‌ی Retry-After صبر کنید.
429quota_exceededسهمیه‌ی پیامک دوره‌ی فعلی تمام شده.
500internal_errorخطای سمت سرور؛ با request_id به پشتیبانی اطلاع دهید.
503service_unavailableسرویس موقتاً در دسترس نیست؛ کمی بعد تلاش کنید.
همیشه request_id را لاگ کنید

اگر به مشکلی برخوردید، همین شناسه را برای پشتیبانی بفرستید تا درخواست شما دقیقاً پیدا شود.

Python

PYTHON
import os, requests

r = requests.post(
    "https://datisrayan.com/api/v1/messages",
    headers={"Authorization": f"Bearer {os.environ['DATIS_API_KEY']}"},
    json={"destinations": ["989121234567"], "content": "کد ورود شما: 4521"},
    timeout=30,
)
if r.status_code == 201:
    print(r.json()["data"]["status"])
else:
    err = r.json()["error"]
    print(err["code"], err["request_id"])

مشخصات OpenAPI

توضیح ماشین‌خوان کل API در فایل openapi-v1.yaml موجود است. می‌توانید آن را مستقیم در Postman یا Insomnia وارد کنید یا با ابزارهای تولید کد، کلاینت هر زبانی را بسازید.

چک‌لیست پیش از رفتن به محیط واقعی

  • کلید در متغیر محیطی سرور است، نه در کد یا مخزن.
  • هر کلید فقط دسترسی‌های لازم را دارد.
  • برای ارسال‌های مهم client_message_id می‌فرستید.
  • خطای 429 را با صبر به اندازه‌ی Retry-After مدیریت می‌کنید.
  • request_id خطاها را لاگ می‌کنید.
  • اگر وبهوک دارید، امضای هر درخواست را بررسی می‌کنید.
